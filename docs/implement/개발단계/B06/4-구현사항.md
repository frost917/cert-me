# B06 4단계 구현사항

기준일: 2026-10-09 · 브랜치: `codex/b06-stage4-implementation` · 상태: 완료

실제 검증 상태는 [TDD 기록](./4-TDD-검증.md)을 따른다. 3단계 최초 설정부터 CA/Leaf 흐름을 네 DB의 실제 HTTPS/SQL 및 race 검사로 확인했다.

## HTTP와 runtime 연결

`internal/adapter/http/authority_routes.go`는 Authority 목록·상세·생성·이름 변경·발급 상태·키 파기·보관의 7개 operation을 제공한다. `leaf_routes.go`는 Leaf series 목록·상세·발급·갱신·재발급·수정·보관과 Certificate 목록·상세를 제공한다. `public_ca_routes.go`는 고정 CA 인증서 ID의 certificate.pem 및 대상 CA부터 Root까지의 chain.pem을 제공한다.

요청은 관리자 세션·현재 권한·Origin/CSRF와 strict JSON 검증 후 typed command로 변환한다. 변경은 If-Match, 생성 및 발급 재시도는 Idempotency-Key 계약을 따른다. 응답은 explicit DTO이며 개인키·전달 토큰을 포함하지 않는다. 관련 리소스 링크는 보호된 Certificate/Leaf series 조회 경로를 가리킨다. 공개 CA 파일은 고정 filename, immutable cache와 ETag 조건부 요청을 지원한다.

`internal/runtime/runtime.go`는 `AuthorityService`, `IssuanceService`, `QueryService`와 기존 key engine·signer·serial/profile ports를 조립한다. HTTP handler가 SQL이나 암호 엔진을 직접 호출하지 않는다.

## 서비스와 저장소

| 실제 모듈 | 구현된 동작 |
| --- | --- |
| `service/issuance_reissue.go` | 모든 재발급에서 새 키 생성. 수령 실패·만료 증거, 키 유출, 긴급 전환의 원본/대상 권한·impact 확인. 기존 전달 종료·폐기·CRL 요구·결과·감사 원자적 반영 |
| `service/issuance_series.go`, `domain/series.go` | 이름·미래 발급 정책 수정과 시리즈 보관. 기존 인증서와 발급 당시 정책을 소급 수정하지 않음 |
| `service/query.go`, `port/queries.go`, `sqlstore/operations/query_pki.go` | 실제 저장된 created_at·보관·전달·CRL 정보 조회. bootstrap CA를 관리 목록에서 paging 전에 제외 |
| `service/query_public_ca.go` | 저장된 CA 인증서/키 세대/issuer 계보의 불변 조회. Leaf/bootstrap 제외, 현재 CA 포인터 교체에 따라 과거 URL 결과를 바꾸지 않음 |
| `port/delivery.go`, `sqlstore/delivery/deliveries.go` | 키 세대의 기존 전달을 transaction 안에서 조회하고 검증 |

현재 인증·권한을 다시 확인한 뒤 저장된 발급 결과를 재생하며 expected version보다 결과 재생을 먼저 수행한다. commit-time 갱신 replay도 신규 발급과 구분한다. CA 인증서 시작 시각은 X.509 정수 초 정밀도에서 즉시 사용 가능하도록 표현하고, 발급자 상태와 기간 확인은 실제 시각을 사용한다. 유출 키 폐기는 아직 NotBefore에 도달하지 않은 미만료 인증서도 포함한다.

SQL migration이나 기존 checksum은 변경하지 않았다. 설치 완료의 감사 target은 UUID가 없는 singleton이므로 NULL로 저장한다. CA 종료 조건 미충족은 `authority_closure_blocked`, 발급 중지는 `issuer_stopped` 업무 충돌로 응답하며 인가 거절은 403을 유지한다. 공개 CA 자격 분류의 내부 관리 scope 조회는 public-read 권한 확인 후 저장된 owner ID에 한정하며, 응답으로 관리 projection을 노출하지 않는다.

## 단계 경계

개인키/Leaf 다운로드 링크, 수령 sink, 폐기 API·CRL worker는 5단계 범위다. 공개 CA 인증서/체인 두 경로는 이번 단계에 연결했다. CRL 실제 게시나 개인키 수령 완료를 주장하지 않는다. runtime 테스트에서 갱신 전 전달 완료를 만드는 부분은 공개 수령 API가 아니라 domain/UOW fixture로 실행한다.

관리 HTML/HTMX 전체 CA 화면과 실제 브라우저 E2E는 이 API 구현의 완료 증거에 포함하지 않는다. 실행한 검증과 coverage·도구·브라우저 범위의 한계는 TDD 기록을 따른다.
