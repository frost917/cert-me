# 1단계 구현사항 — 안전한 HTTP 경계

기준일: 2026-10-04 · 상태: **기본 유틸 구현, 첫 설정 API에 일부 연결**

## 구현된 기능

- `CERT_ME_TRUSTED_PROXY_CIDRS`를 쉼표 구분 CIDR 목록으로 읽고 검증한다. 미설정/빈 값은 프록시를 신뢰하지 않는다.
- 신뢰된 peer에서만 X-Forwarded-For를 해석하고 오른쪽에서 왼쪽으로 신뢰 hop을 검사한다. 비신뢰 peer의 전달 헤더는 무시한다.
- mutation Origin 및 CSRF token GET의 Origin/Referer/Sec-Fetch-Site를 검증한다. 설정 전에는 직접 HTTPS authority를 사용한다.
- CSP, nosniff, no-referrer, frame 차단 헤더를 제공한다.
- ServeMux route pattern만 반환하는 `SafeRouteLabel`을 추가했다. 실제 access logger에 연결되지는 않았다.
- 최초 설정 API에 client IP, Origin/CSRF 검증과 보안 헤더를 연결했다.

## 사용 모듈과 실제 타입

- `internal/config`: `Lookup`, `LoadTrustedProxyCIDRs`, `LoadTrustedProxyCIDRsFromEnv`.
- `internal/adapter/http` (`package httpadapter`): `ResolveClientIP`, `ValidateMutationOrigin`, `ValidateCSRFReadOrigin`, `ApplySecurityHeaders`, `WithSecurityHeaders`, `SafeRouteLabel`.
- 표준 라이브러리 `net/netip`, `net/http`, `net/url`을 사용한다. 별도 HTTP 보안 프레임워크는 없다.

## 의도한 결합

`runtime.Open`이 CIDR 설정을 읽어 HTTP adapter에 전달한다. HTTP adapter는 `contract.RequestMeta`에 검증된 client IP와 server-derived `Principal`을 담아 application service를 호출한다. Handler는 DB·SQL dialect·crypto adapter를 직접 참조하지 않는다. 모든 route가 보안 헤더 middleware를 거치고, 추후 access logger는 원문 URL 대신 route template을 기록한다.

## 남은 작업

- 로그인/관리 API, 다운로드와 HTML/HTMX route 모두 같은 경계를 사용하도록 연결한다.
- `SafeRouteLabel`을 고정 route-template access logger와 연결한다.
- `CERT_ME_TRUSTED_PROXY_CIDRS`의 쉼표 형식과 오류 시작 동작을 운영 문서에 설명한다. 이 문서 변경은 PR 항목이다.
