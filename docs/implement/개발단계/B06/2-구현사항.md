# 2단계 구현사항 — runtime·초기 HTTPS·첫 관리자

기준일: 2026-10-04 · 상태: **코드 구현, 네 DB 장애·경쟁 검증 대기**

## 구현된 기능

- `cert-me serve [--listen]`을 추가했다. 빈 schema만 자동 migrate하고 기존 incomplete/upgrade schema는 명시적인 DB 명령을 요구한다.
- 실행 잠금 아래 encryption generation, encrypted store verifier, `installation` row를 한 트랜잭션으로 만든다. installation이 없는데 업무 행이 있으면 복구 필요로 fail-closed 한다.
- 저장 키를 verifier로 확인한 뒤에만 계속한다. 틀린 키, verifier 누락/세대 불일치, orphan business rows는 listener 시작을 막는다.
- 시작 때 incomplete maintenance/restore 상태를 차단하고, 중단된 delivery transfer를 복구한다.
- TLS의 incomplete change는 reconcile한다. 이미 applied인 active snapshot은 in-memory TLS manager에 복원한다. TLS 이력이 없는 새 설치에서만 bootstrap TLS를 생성하고 SHA-256 지문을 출력한다.
- runtime gate, 2초 주기 writer/lock ownership 감시, fail-closed admission, 최대 30초 graceful shutdown을 연결했다.
- 최초 설정용 `GET /api/v1/setup`, `GET /api/v1/auth/csrf`, `POST /api/v1/setup/admin`을 연결했다. pre-auth HMAC token은 32바이트 nonce cookie, HTTPS origin, 10분 만료에 묶이고 첫 관리자 생성은 자동 로그인하지 않는다.

## 사용 모듈과 실제 작성 타입

- `cmd/cert-me/main.go`: `runServe`, `parseListenAddress`.
- `internal/runtime/runtime.go`: `Options`, `App`, `Open`, `prepareServices`, `prepareTLS`, `ListenAndServe`, `Close`.
- `internal/runtime/gate.go`: `Gate`와 `OpenAdmission`, `Admit`, `FailClosed`, `WaitIdle`.
- `internal/runtime/system.go`: `systemClock`, `randomIDs`, `adminAuthorizer`, `operationalLogger`.
- `internal/storage/sqlstore/installation_bootstrap.go`: `InitialInstallation`, `EnsureInitialInstallation`.
- `internal/storage/sqlstore/startup_recovery.go`: `EnsureNoIncompleteMaintenance`.
- `internal/cryptoengine/keyengine.go`: `KeyEngine.CreateStoreVerifier`, `KeyEngine.VerifyStoreVerifier`.
- `internal/adapter/http/setup.go`: `SetupApplication`, `SetupHandlerConfig`, 내부 `setupHandler`.
- `internal/adapter/http/preauth.go`: pre-auth token 발급·검증.
- 기존 서비스/adapter: `SetupService`, `DistributionService`, `TLSService`, `tlsruntime.ConfigManager`, SQL `core.Store`.

## 의도한 결합

```text
cmd.runServe
  → runtime.Open(Options)
      → config / migration / connection / executionlock
      → sqlstore 초기 설치 + cryptoengine verifier
      → core.Store (UnitOfWork + ReadStore)
      → SetupService / DistributionService 복구 / TLSService
      → ConfigManager와 HTTPS listener
      → SetupHandler → SetupService의 좁은 SetupApplication interface
```

`runtime`가 구성과 수명을 소유한다. Service는 `CommonDeps`의 ports를 사용하고 handler는 service contract만 안다. TLS 복구는 `TLSInstaller`를 통해 수행한다. `Gate`가 fail-closed 되면 새 admission을 닫고 runtime 종료를 요청한다. Setup handler는 인증·CSRF 입력을 검증하고 DTO를 만들며 저장소를 직접 호출하지 않는다.

## 검증 상태와 남은 조건

- `gofmt`, `go build ./...`, `go vet ./...`를 실행했고 통과했다.
- HTTP/runtime/초기 설치 전용 테스트와 네 DB integration/장애 주입 검증은 아직 없다.
- lock monitor는 2초 polling, 최대 60초 probe timeout이다. 실제 writer disconnect 후 종료와 두 번째 프로세스 잠금 경쟁을 네 DB에서 확인해야 한다.
- 현재 setup HTTP surface는 status/CSRF/첫 관리자뿐이다. 로그인·설정 생성·설정 완료는 3단계다.
- 최초 `service_url` 입력 API 경로가 기존 계약에 없다. 기본 URL이나 요청 Host를 추측하지 않고 PR 질문으로 남긴다.
